Plan: a real “Add a connector”

Today the “Add another connector” card is only a note — the one working connector is Claude, and it acts as the person who signed in. This adds a proper way for an admin to connect any outside tool, each with its own key, its own name in the task history, and only the permissions you tick.

  1. Add a connector (admins only): name it, tick what it may do, and choose whose name its changes go under. It gets its own key, shown once, plus step-by-step setup for that tool.
  2. Connected list: every connector with what it can do, whose name it uses, when it was last used, and Make a new key / Disconnect. Disconnecting stops it at once.
  3. Under the hood: the same server Claude already uses, so nothing new to maintain. Each key is stored only as a fingerprint; every change it makes is recorded in the task's history as “via n8n” (or whatever you named it).

DecideWhose name should a connector's changes go under — its own name (e.g. “n8n”), or a person you pick? DecideShould a connector also be told when something happens (e.g. “a task moved to Ready to Publish → tell n8n”)? That's what n8n triggers need; it can come later.
